# UX 调研与改进

对照 [00-pain-points.md](00-pain-points.md) / [01-design.md](01-design.md) Architecture v1.5。
本文只补 **人怎么把闭环走完**，不改身份、controller ownership、iroh 路径模型。

调研对象：RustDesk Custom Client / Address Book、Tailscale status + device approval、Syncthing 交换 Device ID、wush 口令、sshx 一条命令出 URL、VS Code Ports / Remote Tunnel、MCP stdio 配置摩擦。

## 1. v1.5 继续保留的正确方向

- 合作者零输入：enrollment 打进 artifact。
- Controller 长期持有 listener / task，CLI/MCP 退出不会拆台。
- 不逐条弹确认，权限前置到 mint profile。
- Host 必须可见、可退出。
- Relay 当正常路径，不把「走中继」写成失败。
- MCP 是 adapter；工具结果有界。

这些不要为了「更炫」再拆掉。

## 2. 仍然卡手的地方

当前设计把成功定义成协议闭环，用户却会卡在协议之前或之后：

| 卡点 | 现在文档怎么写 | 实际体验 |
|---|---|---|
| 你这边还没起 controller | 要先 `clew controller` | agent 一调 MCP 就失败，报错像网络问题 |
| 发给朋友的是裸 exe | mint + pack 两步 | 朋友收到文件不知道点什么，Windows 先吓一跳 |
| Host 状态写 Relay/Direct | §15 | 合作者看不懂，以为「中继」是坏了 |
| 半提交 enrollment | 风险里提到 | 朋友重开 exe 以为坏了，你这边多出一台幽灵设备 |
| 转发成功 | 有 `forward.add` | 没有「打开 http://127.0.0.1:L」这种收尾 |
| 多设备 | ambiguous-device 错误 | agent 不会读错误列表，会乱选或空转 |
| 你不在电脑前 | 无通知 | 朋友已上线，agent 还在重试 |

## 3. 可借鉴的具体体验

### 3.1 交付物自带说明书（RustDesk Custom Client）

RustDesk Pro 把服务器、密钥、品牌打进安装包，对方不用填网络。真正差在：生成器还会给出「发给用户的那句话」。Clew 的 `mint`/`pack` 应产出 **artifact + 一段可粘贴聊天稿**，而不是两个技术命令。

建议一条命令：

```text
clew invite alice --profile research-full --target windows-x86_64
```

输出：

- `Alice-Clew-Windows.zip` / `Alice-Clew-macOS.zip` 等按平台 Site Kit（内含对应平台 Clew 与 `site.clew`）
- `alice.md` / 包内“开始这里”：打开后应看到什么、如何退出、目标机连不上时如何用同一份包启动连接助手
- 你这边：`clew status` / GUI 先出现 Site「Alice · 等待电脑加入」，真实设备 enrollment 后再显示 hostname 设备名

### 3.2 状态用大白话（Tailscale status）

`tailscale status` 写 `active; direct` / `relay nyc`，运维能看。合作者窗口不要写 `Relay`。

建议文案：

| 内部状态 | 窗口大字 | 一行解释 |
|---|---|---|
| Connecting | 正在连接 | 正在找到对方电脑 |
| Relay | 已连接 | 现在可用；网络允许时会自动更快 |
| Direct | 已连接（直连） | 当前是点对点 |
| Reconnecting | 正在重连 | 网络抖了一下，请稍等 |
| Offline | 未连上 | 把这扇窗开着，或把截图发回 |

托盘色点沿用 assets 里的绿/琥珀/灰。技术细节放「详情」折叠，给排障用。

### 3.3 活动可见，但不打断（远控惯例）

TeamViewer / RustDesk 会让被控方知道「有人连着」。Clew 不弹「是否允许这条 ls」，但窗口应有一行 **此刻在做什么**：

```text
已连接 · 正在读取 D:\\proj\\README.md
已连接 · 命令运行中（12s）
已连接 · 传到 34%
已连接 · 本机 1080 代理开着
```

这是信任，不是关卡。退出仍然一键，能力立刻没。

### 3.4 本机端口的收尾（VS Code Ports）

VS Code 转发后会通知 `localhost:4123`。Clew 的 `forward.add` / `proxy.add` 成功后应：

- CLI 打印可点的 `http://127.0.0.1:L`（若 dest 像 http）和 `socks5://127.0.0.1:1080`
- MCP 工具结果里带 `listen_url`，让 agent 直接告诉人
- 端口占用时自动换端口并声明实际端口，不要闷声失败

### 3.5 名字要像“地点/电脑”，不是邀请对象复制四遍

邀请时的 `Alice 实验室` 是 Site 名，不是每台电脑的设备名。第一次 enrollment 默认取 hostname：

```text
Alice 实验室
  GPU-01       已连接
  CryoEM-PC    已连接
  Lab-PC       连接助手
```

碰撞时不要显示 `GPU-01 (2)`。Controller 给碰撞组每台设备加一个由 DeviceId 稳定派生的 **5 字符短码**，例如 `GPU-01-K7M4Q` / `GPU-01-P2D8N`；使用避开易混字符的 Crockford Base32。短码只为区分机器，不泄露 MAC/序列号，也不是认证凭据。碰撞一旦发生，带 tag 的自动名就持久化，不因为另一台离线/删除而变回 `GPU-01`；控制者仍可随时改成更有意义的名字。

给 agent 的首选 selector 是 `Alice 实验室/GPU-01-K7M4Q`；无碰撞时仍可以是 `Alice 实验室/GPU-01`。短名只在在线 executable devices 中唯一时才成立。helper-only 不进入 Read/Shell/File 候选；多候选时 MCP 返回名字列表，让 agent 明确询问用户，而不是挑第一台。

### 3.6 Controller 对用户隐身启动

Tailscale 是装完就有 daemon。Clew 若要求先开一个终端跑 `clew controller`，agent 集成会碎。

建议：

- `clew mcp` / `clew ls` / `clew forward` 发现没有 controller 就 **拉起并接管单实例**（或提示「已在托盘运行」）
- Windows/macOS controller 可以有一个极简托盘：设备上线气泡「Alice 已连接」
- 仍保持单实例，第二进程变 client

合作者侧继续禁止静默；**你这边**静默托盘是合理的，因为你是控制者。

### 3.7 重开、更新、换电脑要分清

朋友经常会双击两次、杀毒删了重新下载、把新版程序覆盖旧版。规则固定：

1. **同机器 + 同 OS user + 同 Site**：已有 DeviceKey 就跳过 enrollment；若 Clew 已在运行，第二次启动只把原窗口叫出来，不创建第二台设备。
2. **同机器换新版 ClientFlavor**：继续复用本机 DeviceKey；`site.clew` 只用于找 Site/Controller，不把更新误当新设备。
3. **换电脑/换 OS user**：这是新 SiteMember，使用 hostname 得到新的设备名；旧设备是否保留由控制者决定，不拿“同名 Alice”推断它是替换关系。
4. **半提交失败**：本机没有 DeviceKey 且 claim 已不可恢复时，人话提示向控制者重新发加入材料，不静默创建幽灵设备。

### 3.8 给 agent 的安装摩擦（MCP）

stdio MCP 要用户改 Cursor/Claude 配置。一次性减少摩擦：

```text
clew mcp install --cursor
clew mcp install --claude
```

写出 config snippet，并 `clew mcp doctor` 检查：controller 在不在、有无在线设备、本机 4877 是否开着。

工具描述用短英文、带默认 root 和限制，避免模型一上来 `Grep /`。例如 Shell description 写明 working root、timeout、不要扫盘。

### 3.9 预期时间（sshx / wush）

sshx 追求一秒出 URL；iroh 第一次走中继可能要几秒到十几秒。窗口不要停在空白。

Connecting 阶段用三步进度，即使是假进度也好过转圈：

```text
1/3 正在联网
2/3 正在登记这台电脑
3/3 正在接通
```

超过 ~20s 仍 Connecting：换一行「还在连，常见原因是公司网较慢，请继续开着」。不要抛 raw iroh error。

### 3.10 不要向合作者要管理员

v1 工具、转发、代理都不需要提权。安装/服务/UAC 一律不做。RustDesk portable 第一次 P2P 会撞防火墙弹窗；Clew 只出站 QUIC/HTTPS，应避免听端口。Host 不 bind 公网。

### 3.11 多机 / 内网：不要让朋友理解 Node + GW

如果目标电脑不能直接联网，体验目标不是“教会朋友部署 gateway”，而是生成一个 **Site Kit**。朋友只在参与的电脑上打开 Clew；能联网的 Site member 自动提供连接助手能力，无法直连的目标机自动在 LAN 找它。

常见两机路径：

```text
联网电脑：双击 -> “连接已就绪，正在等待附近电脑”
目标电脑：双击 -> “正在连接” -> “已连接”
```

谁先开都可以。

内部可以有 `SiteId`、`CONNECTOR`、connector lease；朋友端不出现这些词。Connector-only 电脑窗口明确写“只帮助附近电脑连接，不开放本机文件和命令”。

同一 Site 允许多个连接助手自动 failover；目标机不绑定具体 GatewayId。mDNS/LAN discovery 失败时，fallback 优先是从 helper 生成一个 `附近连接.clew` 小文件复制过去，而不是让朋友填写 IP。

完整设计见 [04-site-connector-ux.md](04-site-connector-ux.md)。

进一步收紧：**不要要求控制者在发邀请前判断朋友需不需要 gateway。所有 GUI 邀请默认就是 site-capable 的 Site Kit。** 单机只启动一个成员；如果目标机连接不上，朋友拿同一份包去附近能联网的电脑打开“帮助其它电脑连接”即可，不需要控制者重新生成第二份邀请。
Connector 的体验简单不等于安全模型含糊：v1.5 明确 Target↔Controller 始终有一层 InnerSession。helper 只搬密文，朋友看到的“只帮助连接”与实现一致，而不是“实际上可以读 Shell/文件，只是 UI 不说”。

### 3.11.1 `site.clew` 被拆丢是正常事故，不是高级排障

聊天软件、网盘和用户手工拖文件很容易让 exe/app 与 `site.clew` 分开。启动页固定按这个顺序解决：显式拖入/选择 `.clew` → 程序旁边的 `site.clew` → 本机已有 membership → 缺失页。

缺失页只说：

```text
还缺一个邀请文件。
请把 site.clew 和这个程序放在同一个文件夹，
或把 site.clew 拖到这里。

[ 选择邀请文件 ]
```

若检测到从压缩包临时目录直接运行，优先说“请先全部解压这个压缩包，再打开程序”。聊天稿也主动写“请完整解压，两个文件放在一起”。

### 3.12 成功后退居托盘，不占朋友主屏幕

朋友端的主窗口只负责“确认 Clew 已经工作”和必要时查看详情，不应该长期占桌面。成熟远控/同步类应用的共同模式值得直接采用：运行状态沉到系统托盘/菜单栏，窗口关闭不等于进程退出，真正停止必须是显式 Exit。

Clew 规则固定为：

```text
双击 -> 主窗口显示连接过程 -> 已连接
                         ↓
                 朋友可最小化 / 点 X
                         ↓
                   托盘继续运行
```

不能出现“空闲时点 X 是隐藏，有任务时点 X 却断开”的上下文语义。朋友不应该因为收窗口而误杀远程会话。

托盘承担三个作用：

1. **看状态**：图标 + hover/菜单首行显示“已连接 / 正在重连 / 已暂停”，helper-only 显示“正在帮助 N 台电脑”；
2. **快速回来**：点图标/菜单“显示 Clew”恢复主窗口；
3. **明确控制**：`暂时断开/重新连接` 与 `退出并断开` 分开。

托盘 tooltip 只显示粗粒度活动，不显示具体文件路径、Shell 命令或敏感目标。高级排障放主窗口详情或隐藏 debug 入口，普通右键菜单不堆网络术语。

第一次隐藏到托盘时给一次系统提示“Clew 会继续在托盘运行”，不要求确认；以后不再打扰。如果启用登录后自动运行，应该直接 tray-only 启动，避免每次登录弹一个完整窗口。
睡眠不是退出：Clew 不阻止合盖/系统睡眠；唤醒后自动重连，helper 自动重新提供附近连接。锁屏本身不显示成离线。Controller 只有在确实收到 suspend 通知时才标“睡眠”，否则只写“离线/等待连接”。

Linux v1 没有可靠 tray 时走另一条人话路径：前台运行、持续显示一行状态，`Ctrl-C` = 退出并断开；绝不把进程隐藏到用户找不到的后台。
后续会增加一个明确标成 **高级：后台长期可用** 的入口，而不是把 v1 行为偷偷改掉。Linux 首选 `systemd --user`；机器级场景再提供 Windows Service / Linux system service。启用时 UI 必须解释“关闭窗口不等于停止后台服务”，并提供独立的“停止后台服务 / 卸载服务”。machine service 若只做连接助手，应默认不开放本机文件和命令。

### 3.13 分发穿搭：降低“陌生程序”心理摩擦

连接步骤已经为零输入以后，下一层体验不是继续减少一个不存在的按钮，而是让朋友一眼确认“这是你发来的那个工具”。远控产品的 white-label/custom-client 设计普遍会开放应用名、Logo、图标、颜色和关键文案；ISL Online 还提供 customization duplicate/default 和实时 preview。

Clew 因此把穿搭放到**控制者侧**，不把主题设置推给朋友：

```text
你：选 Research Lab preset -> 换 Logo/程序名/颜色 -> 保存
朋友：仍然只是双击 Site Kit
```

日常邀请里“外观”已有默认值，不成为新的必填步骤。helper-only 自动继承同一 Outfit，只换角色文案。

GUI 必须实时预览主窗口 + tray + Site Kit；尤其要预览 16–24px 托盘图标，避免大 Logo 缩小后不可辨认。完整设计见 [05-distribution-studio.md](05-distribution-studio.md)。

### 3.14 控制者也要能收口、回看、备份

朋友的“退出并断开”保留，但控制者端必须有等价且更强的收口：设备菜单“停止这台”，Site/邀请菜单“停止继续加入 / 作废这份分发包 / 停止整个 Site”。“关闭邀请”只阻止新机器加入，**不等于**撤销已经 enrollment 的设备；这两种动作必须分开。

Controller 增加一个本机 Activity 视图，回答“刚才 agent 在 GPU-01 读了什么路径、跑了什么命令、传了多少数据”；日志有界、本机保存、可清空，不做云端审计平台。

第一次生成邀请后提示一次“建议备份控制者身份”。如果 ControllerKey 无备份丢失，产品直接说“以前的连接不会自动迁移，需要重新邀请”，不能让朋友端自动信任一个新 key。

## 4. 建议纳入 v1 的 UX 增量（小，但不该缺）

按投入排序：

1. **`clew invite`**：artifact + 聊天稿 +「等待上线」。
2. **Host 文案**：已连接 / 正在重连；详情里才写中继/直连。
3. **活动一行**：读文件 / 跑命令 / 传文件 / 开着代理。
4. **CLI/MCP 自动拉起 controller**（单实例）。
5. **设备用人名**；多设备错误列出名字。
6. **forward/proxy 成功返回 listen_url**，端口冲突则换端口。
7. **同设备重开跳过 enrollment**；失败时 `invite --replace`。
8. **`clew mcp doctor` + 一份现成 MCP JSON 片段**。
9. **Site Kit**：多机/内网时仍保持“每台电脑只双击一次”，不出现 gateway 配置页。
10. **Tray-first Host**：朋友确认“已连接”后可直接收起窗口；X/最小化都只隐藏，显式 Exit 才断开。
11. **Distribution Studio**：控制者用 preset + live preview 定制 app name/icon/logo/color/strings；朋友操作数不增加。
12. **Sidecar recovery**：`site.clew` 拆丢时有固定恢复页/拖入/选择文件，不报 raw missing-sidecar。
13. **Revocation + backup**：控制者能停止设备/邀请/Site，并备份 Controller identity。
14. **Activity + sleep**：本机活动记录；睡眠/唤醒自动恢复；Linux foreground fallback。

这些都不增加新的远程协议角色，而是把 Architecture v1.5 已有状态用更符合人的方式露出来。

## 5. 明确可以后置的 UX

- 自动探测对方 `localhost:3000` 并提议转发（VS Code 那套，V4 之后再做）。
- Controller 完整 GUI（有托盘通知就够）。
- QR / 浏览器加入（sshx 模型，和「预打包 artifact」不是同一条产品线）。
- 合作者侧「只读旁观 agent 终端」（sshx 画布），Clew 的用户是 agent 不是结对编程。
- MagicDNS 式主机名（`alice.clew`），有人名就够。
- 远程桌面画面。

## 6. 文案禁区

不要对用户说：P2P、DERP、iroh、QUIC、ALPN、enrollment capability、DeviceKey。

对合作者只说：连接、已连接、正在重连、退出。
对控制者 CLI 可以说中继/直连，因为要排障。

不要承诺「断线后网页转发还在刷」。Architecture v1.5 仍明确 TCP 不透明迁移；UI 在 connection 丢失时应把已建立的转发连接标成中断，而不是假装还活着。

## 7. 一条更顺的产品路径

```text
你:  GUI/clew invite alice --outfit huang-lab --profile research-full
     → 直接生成已经穿好 Huang Lab 外观的 Site Kit 和说明

Alice: 双击 → 看见「正在连接」→「已连接」
       可把窗口收进托盘；需要停止时从窗口/托盘点「退出并断开」

你:  agent 已经能 Read/Shell
     需要网站时: clew forward add --dest 127.0.0.1:3000
     → 打印 http://127.0.0.1:13100
```

若这条路上还要人理解 worm、controller、Relay、gateway、route 这些词，体验就还没做完。

多机/内网的等价人话路径见 [04-site-connector-ux.md](04-site-connector-ux.md)：朋友只需要把同一 Site Kit 放到参与电脑上并双击。
